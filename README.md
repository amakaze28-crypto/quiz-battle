# 看護模試バトル（4人・レートマッチング）

React + Tailwind / Node.js + Socket.io / Firebase (Auth + Firestore)

```
quiz-app/
├─ client/   React(Vite) … Vercel にデプロイ
├─ server/   Node.js + Socket.io + 管理API … Render 等にデプロイ
└─ firestore.rules
```

## 1. Firebase 設定
1. プロジェクト作成 → Authentication で **Google** を有効化
2. Firestore を作成し、`firestore.rules` の内容を貼り付けて公開
3. プロジェクト設定 → ウェブアプリを追加し、設定値を `client/.env` に記入（`client/.env.example` 参照）
4. プロジェクト設定 → サービスアカウント → 新しい秘密鍵を生成。JSON を**1行にして**サーバーの環境変数 `FIREBASE_SERVICE_ACCOUNT` に設定
5. 管理者にしたいGoogleアカウントのメールを、サーバーの環境変数 `ADMIN_EMAILS`（カンマ区切り）に設定。そのアカウントでログインすると管理者画面が開きます

## 2. ローカル実行
```bash
cd server && npm install && cp .env.example .env && npm run dev   # :3001
cd client && npm install && cp .env.example .env && npm run dev   # :5173
```
`FIREBASE_SERVICE_ACCOUNT` が空のサーバーは **開発モード**（メモリ保存・トークン `dev:名前` を許可、`dev:admin` は管理者）で動きます。
4人対戦の動作確認: `cd server && npm run simulate`（別ターミナルでサーバー起動中に実行）。
テスト用に `MATCH_SIZE=2` や `QUESTION_TIME_MS=5000` で短縮できます。

## 3. デプロイ
- **Render**: Root Directory=`server`、Build=`npm install`、Start=`npm start`。環境変数 `FIREBASE_SERVICE_ACCOUNT`、`ADMIN_EMAILS`、`CLIENT_ORIGIN`(VercelのURL)、`NODE_ENV=production`
- **Vercel**: Root Directory=`client`。環境変数 `VITE_FB_*` と `VITE_SERVER_URL`(RenderのURL)
- Firebase Auth の「承認済みドメイン」にVercelのドメインを追加
- Render無料枠はスリープします。`/health` を外部監視(UptimeRobot等)で定期的に叩くと起きやすくなります

## 4. 管理者画面
管理者アカウントでログインすると管理者画面が最初に開きます（アイコンメニューで「プレイ画面」と切り替え可）。
- **問題**: 追加／編集／削除、公開・非公開、検索・絞り込み、**JSON取り込み**（何百問でも一括。複数ファイルを同時に選択でき、同じ問題文は重複スキップ）
- **プレイヤー**: レート順の一覧、名前・メール・UID検索、**BAN／解除**、コイン・魔法の砂の増減
- **メッセージ**: プレイヤーからの**通報**が「誰から誰へ・理由・コメント」で届きます。対応済みの切り替えと、通報先のBANができます
- **メール**: 運営からのプレゼントメール（コイン・魔法の砂付き。全員 or UID指定）
- **アイテム**: アイコン／フレーム／バナーの登録（画像・名前・レア度・砂の価格・ショップ販売／ガチャ封入の切替）。画像は自動で整形されます（フレームは**中央が透明な正方形**のPNG推奨）
- **ミッション**: ウィークリー／スペシャルの追加・編集・無効化・削除
- **設定**: ミッション報酬コイン、改名コスト、Secondary確率、**ガチャ設定**（1回のコイン、アイテム／砂の比率、レア度別の比率・砂の量、被り時の砂）

問題JSONの形式（`answer` は0始まり）:
```json
[{ "question": "日本の首都は？", "choices": ["大阪","京都","東京","名古屋"], "answer": 2, "explanation": "任意" }]
```

## 5. プレイヤー向け機能
- **ホーム**: 画像のホーム画面。ランクマッチ／メール／ミッション／ショップ／フレンド／ガチャ。赤い通知は未受け取り・未読のときだけ表示
- **メール**: 運営からのプレゼントを受け取り
- **ミッション**: デイリー・ウィークリー（毎週月曜0時JST更新）・スペシャル（期間限定）の3タブ。ウィークリー／スペシャルは管理画面の「ミッション」で自由に追加できます（内容=マッチ数・勝利数・ログイン日数・正解数、目標、報酬コイン/砂、期間、タブごと最大5件）
- **デイリーミッション**（毎日0時JSTに更新）: ログインする／5マッチプレイする／3勝する。報酬は設定画面の値
  - 「勝ち」は、その試合のレート変動がプラスだった場合です
- **フレンド**: フレンドコードで申請→承認。オンライン表示・最終ログイン・現在のランクが見えます（上限50人）
- **共通背景・UIパーツ**: 送っていただいた背景画像（`client/public/ui/bg.jpg`）をローディング・プロフィール・設定・メール・メニュー等の背景に使用。ホーム/ミッション画像から切り抜いた枠・ボタン（`panel.png` `plate.png` `btn-blue.png`）を `client/src/Ui.jsx` の `Panel` `Plate` `Btn` で共通利用（新しい画面もこれを使えば同じ雰囲気になります）
- **縦画面・横画面**: どの画面も縦横どちらでも使えます。画像ベースの画面（ホーム等）は画面の高さに合わせて中央に表示し、左右は共通背景で埋めます
- **BGM・効果音**: タイトル／ホーム系／対戦で曲が切り替わり、ボタン・マッチ成立・出題・正解/不正解・Secondary・勝敗・ガチャ・コイン獲得で効果音が鳴ります。設定画面（タイトルの設定も可）でオン/オフと音量を調整できます。音源は `client/public/audio/` の同名ファイルを差し替えるだけで変更できます（`bgm-title.mp3`=タイトル、`bgm-home.mp3`=ホーム系、`bgm-battle1〜3.mp3`=対戦（マッチ成立のたびに3曲からランダム）、`se-correct.mp3`=◯、`se-wrong.mp3`=×、`se-tap.mp3`=タップ、`se-queue.mp3`=ランクマッチを押したとき、`se-match.mp3`=マッチ成立。その他の効果音は仮の自作音）。タップ音は主要ボタン（青・金・赤のボタン）だけに鳴り、タブ・ナビ・解答などでは鳴りません。他のボタンに鳴らしたい場合は `data-sfx` 属性を付けます。BGMは曲の先頭・末尾の無音を自動で取り除き、途切れずにループします
- **Secondary**: 出題の前に「SECONDARY この問題の得点は2倍！」と全員に告知され、その問題は正解した全員の得点が2倍（確率は管理画面で設定、既定5%）
- **対戦中の順位**: 得点だけで決まり、同点は同率（1位・1位・3位・4位）。各カードに平均解答時間と「現在◯位」を表示（並びだけ、同点なら平均解答時間が速い順）。正解は◯、不正解・時間切れは×が画面に出ます
- **bot**: ダイヤ帯まで、待ち時間が5〜12秒（管理画面で変更可）を超えると、同じランク帯のbotが加わって対戦が始まります。botの正答率はそのランク帯のbot以外のプレイヤーの平均正答率、解答までの秒数はその帯の平均解答秒数の −1〜＋5秒です（データが少ないうちは正答率60%・平均12秒）。botはレート変動・通報の対象外で、マスター以上には出ません。管理画面の設定でオン/オフできます
- **タイトル画面**: タップでスタート（未ログインならGoogleログイン）。引き継ぎ・設定あり
- **ガチャ**: コインで1回／10回。アイテム（アイコン・フレーム・バナー）か魔法の砂が出ます。被りは砂に変換（コモン10/アンコモン50/レア100/エピック500/レジェンダリー1000）
- **ショップ**: 魔法の砂でアイコン・フレーム・バナーを購入・装備。初期アイコンは同梱の画像
- **改名**: 初回無料、2回目以降はコイン
- **通報**: 対戦中（右上）と試合終了後に、同じ試合の相手を通報できます。理由は チート行為／不適切な名前／その他（コメント必須）。同じ試合で同じ相手は1回まで
- **対戦画面**: 画像の対戦画面（チャットなし）。カードは得点順に並び、金枠が現在のトップ

## 6. ルール実装メモ
- **ランク表示**: 画像どおりのバッジ（`client/public/ranks/*.webp`、下の板に現在のシーズン「S10」などを自動で表示）。右上のアイコンをタップすると プロフィール／設定／ログアウト（赤・確認あり）
- **ランク**: ルーキー〜ダイヤは Pt の範囲で決定（各サブランク5→1）。7000pt でマスター(MR1500)に昇格し、以降は MR が増減。MR上位100人が表示上「エンペラー」（1分ごとに更新）
- **ポイント増減と降格**: ポイントは全ランクで増減します。
  - ルーキー〜ゴールド: ティア（ルーキー/ブロンズ/シルバー/ゴールド）は降格しません。現在のティアの下限（0/500/1250/2250）で止まり、ティア内のサブランク(5〜1)は上下します
  - プラチナ・ダイヤ: サブランクもティアも降格します（ダイヤ→プラチナ）。ただしプラチナの下限3500でゴールドには落ちません
  - マスターには降格しません（MRは増減）。エンペラーはMR順位から外れるとマスターに戻ります
  - 変更したい場合は `server/src/rating.js` の `applyDelta` と `server/src/rank.js` の `PLATINUM_*` を編集
- **マッチング**: レート差 300 から開始し、待つほど許容差が 30/秒で広がる。マスターは `7000 + (MR-1500)` として比較
- **解答ルール**: 他の人が正解した後も、全員が解答するか制限時間(60秒)になるまで解答できます。正解した問題の得点は **100点 × タイム倍率**（下の「得点とレート」参照）で、**5%（設定で変更可）でSecondaryが発動しその問題の得点が2倍**。誤答は0点。解答時間は正解した人=自分のタイム、誤答・未回答=60秒。通信遅延はRTTの半分(上限250ms)で補正し、クライアント申告タイムは信用しません
- **レート計算**: 下の「得点とレート」を参照（`server/src/rating.js`）
- 切断した人はその試合の残りを未回答扱い。全員切断した試合はレート変動なし（再接続は未実装）

## バナー表記・位置調整・ログイン数
- 「カードフレーム」は **バナー**、従来の帯画像は **対戦バナー** という名前になりました（管理画面・ショップ・ガチャ・プロフィール共通）。
- 管理画面 > アイテム: 各行をタップすると見た目を確認できます（バナーは実際のプレイヤーカード表示）。バナーでは「アイコンなどの位置を調整する」から、アイコン・名前板・ランク板・キャラ・バッジの位置をスライダーで調整し、1枚だけ／同じ台紙タイプ全部に保存できます（`cardlayouts` コレクション、公開API `GET /card-layouts`）。
- プロフィール「カードの設定」: アイコンフレーム／バナー／対戦バナーを選べます。ショップにもバナー・対戦バナーのタブがあります。
- 管理画面 > 設定: 現在のオンライン人数、日別のログイン人数、時間別のログイン数と同時接続の最高人数のグラフ（日本時間、日付で切替）。記録は `loginstats` コレクション（1時間ごと）。

- **メンテナンス**: 管理画面 > 設定 の一番上。オンにすると、タイトル画面に「メンテナンス中」（任意のメッセージ付き）と表示され、管理者以外はログイン不可（API・Socketとも拒否。接続中の人もタイトルへ戻る）。管理者はそのまま入れます。公開API `GET /maintenance`。
- **位置調整**: 管理画面 > アイテムで、バナー・アイコンフレームの行に「位置調整」ボタン。追加時も、画像を選ぶとその場で位置を調整できます（バナー=アイコン/名前/ランク/キャラ/バッジの配置、アイコンフレーム=大きさと縦横のずれ）。保存先は `cardlayouts` / `framefits` コレクション。
- バナー画像のアップロードは縦横比を保って最大1024×1536で保存します（以前は正方形に切り抜かれていた不具合を修正）。

## Firestore の読み取りを減らす仕組み（無料枠対策）
無料枠は 1日 読み取り5万 / 書き込み2万。次の工夫で、普段の読み取りをほぼ「ログイン時の1回」だけにしています（**サーバーは1台で動かす前提**です）。

- **問題はまとめて保存**: `qbundles` コレクションに300問ずつ1ドキュメントで保存し、全問題をメモリに保持。1万問でも起動時の読み取りは約35回。問題の編集・公開切替・ファイル操作は、該当ドキュメントだけ書き直します（読み取りなし）。
  - 旧形式（`questions` コレクション）は、初回起動時に自動で `qbundles` へ引っ越します。旧データは残るので、移行を確認したら Firebase コンソールで `questions` コレクションを削除して構いません。
- **アイテム・セット・ガチャ・バナー位置・フレーム位置・バッジ・メール・音源の一覧はメモリキャッシュ**: 起動後の最初の1回だけ読み、管理画面で保存したときに Firestore とメモリの両方を更新します。
- **ユーザーはメモリに保持**（30分操作がなければ破棄）。書き込みは Firestore とメモリの両方へ。
  - Firebase コンソールで直接ユーザーの値を書き換えた場合は、サーバーの再起動か30分の経過まで反映されません。値の変更は管理画面から行ってください。
- **ランキング/エンペラー**: 1時間ごとの更新です（順位に関わる変更があったときだけ、最短55分おきに読み直し）。そのため、ランキング画面とエンペラー表示は最大1時間遅れます。
- **bot用の統計**: ユーザー100人分を1回の走査でまとめて集計し、10分キャッシュ（人数が少ない帯は既定値＝正答率60%・平均12秒を使います）。
- **管理画面のプレイヤー一覧**: 120秒キャッシュ（BAN・コイン付与などは一覧にも即反映）。
- **ログイン数の記録**: 今の1時間ぶんをメモリに持ち、1分ごとにまとめて書き込み。
- 管理画面「設定」に **Firestore 使用量の目安** を追加（サーバー起動からの読み取り/書き込み回数と、項目別の内訳。再起動で0に戻ります）。

### JSON取り込み
「取り込み先」で **既存のファイル** を選ぶと、そのファイルの末尾に追加され、分野もそのファイルの設定が使われます（JSON内の `category` は無視）。新しいファイルにしたいときは「新しいファイル」を選び、名前を入れます。

## 得点とレート（試合内スコアとレートptは別物）
**1. 試合内スコア（勝敗・順位を決める得点）**
- 正解した問題の得点 = `100 × タイム倍率`。倍率は `2 − 解答秒数/60`（0秒=2.0倍 → 60秒=1.0倍の直線）。誤答・未回答は0点。Secondaryの問題はさらに2倍。
  - 例: 6秒で正解=190点 / 30秒=150点 / 60秒=100点（Secondaryなら×2）。10問の満点は約2000点。
- 順位は合計スコアだけで決まります。**同点は同率**（1位・1位・3位・4位）。平均解答時間は順位に使いません（表示のみ）。

**2. レートpt（pt / mr）の増減**
1. 順位の基本値（4人）: 1位 +20 / 2位 +7 / 3位 −7 / 4位 −20。同率の人は、その順位ぶんの基本値の平均（例: 同率1位2人なら +13.5 ずつ。合計は変わらない）。全員同点なら全員0。
2. 点差の補正: `(自分のスコア − 他の平均) ÷ 100 × 2`、−10〜+10。
3. レート補正: `1 + (増減の符号) × (他の平均レート − 自分のレート) ÷ 1000`、0.5〜1.5倍（今までと同じ）。
4. 最終値 = `round((基本値 + 点差補正) × レート補正)`、−50〜+50。プラスなら勝ち、マイナスなら負けとして記録。
- 以前の「スピードボーナス」は、スコアのタイム倍率に入ったので、レート側からは外しました。
- 数値を変えたいときは `server/src/rating.js` の定数（`placeBases` / `MARGIN_PER_100` / `MARGIN_CAP` / `RATE_CAP` / `timeFactor`）を編集します。

## アイテムの保存形式（読み取り削減）
- 名前・価格・レア度などの文字の情報は、500件ずつ1ドキュメント（`itembundles`）にまとめ、全件をメモリに持ちます。起動時の読み取りは、アイテム1,000個でも2回です。
- 画像は1枚ずつ別ドキュメント（`itemimages`）に置き、表示されたときに読んでメモリに覚えます（上限約40MB）。ブラウザ側には1年キャッシュさせています。
- **旧形式の `items` コレクション（画像つき）は使いません。** 旧形式のアイテムは、新しい形式では出てこなくなります（＝全削除した状態から始まります）。Firebaseコンソールで `items` コレクションを削除して構いません（`questions` も、移行後は不要です）。
- 管理画面のアイテム詳細に「このアイテムを削除」ボタンを追加しました。画像と位置調整も消えます。すでに持っているユーザーの持ち物からは消さず、装備中だった場合は初期の見た目（アイコン・キャラ・フレームなし）に戻ります。
- バナー（カードフレーム）や、アイコンフレームの位置調整は、新しく追加し直したアイテムに対して行ってください。

## 追加アップデート（ランクリセット・BGM・ガチャ設定ほか）
- **通報**: プロフィールの「間違えた問題」の詳細から問題を通報できます。
- **バナー統合**: 「対戦バナー」の項目を削除。バナー（card）の絵がマッチ成立表示・フレンドの帯にも使われます。
- **シーズンのランクリセット**: 管理者「シーズン」で「完全リセット」か「全員N段階降格」を選べます（ルーキー5〜ダイヤ1〜マスターの30段階換算）。
- **戦闘BGM**: 管理者「音源」タブの「戦闘曲の追加」から追加。「みんなが使える」曲は全員の選択肢とランダム候補に入り、「ショップで販売」の曲はショップの「戦闘BGM」タブで購入・試聴・選択できます。選択は端末ごとに保存。音源は `sounds`/`soundchunks`（slot名 `bgm_<アイテムID>`）に保存。
- **ガチャ設定**: 管理者「ガチャ」タブに集約。レア度ごとの出現率、砂とアイテムの比率、砂の量、被り砂を別々に設定。ガチャごとの個別設定も可（旧設定は自動変換）。
- **ショップ並び替え**: 標準／安い順／レア度順／新しい順。
- **ガチャのバナー**: 画像読み込み中は灰色の「読み込み中...」を表示。
- **AdSense**: `client/index.html` の `<head>` にスクリプトを追加済み。

## 連勝ボーナス
- レートが増えた試合だけ連勝が続き、変動なし・減少で0に戻ります。
- 3連勝目から、レート増加に倍率: 3連勝1.25 / 4連勝1.5 … 0.25ずつ増え、10連勝の3.0倍で頭打ち（以降は同じ）。
- 倍率は上限50で丸めた後に掛けるため、連勝中は50を超えることがあります（`server/src/rating.js` の `streakMult`）。
- 2連勝以上でホームに「🔥N連勝中！」を表示。倍率は裏の計算のみで、結果画面は増えた数字だけ表示。

## 遊び方ガイド・通報の追加
- アイコンメニューに「遊び方」（`client/src/Guide.jsx`）。文面はそこを編集すれば変えられます。
- プロフィールの「間違えた問題」に分野タグを表示。通報の理由に「タグがおかしい」「解説が間違っている」を追加（このふたつはプロフィールの間違えた問題からのみ。サーバー側でも、自分の間違えた問題以外は拒否）。
- ガチャ画面の背景は、焼き込まれていたステータス枠を消した `gacha2.jpg` に差し替え、枠はホームと同じ `HudFrame`（Hud.jsx）で描画。

## 切断と再接続
- 対戦中に通信が切れても、部屋は残ります（全員いなくなった場合は60秒後に閉じます）。
- ログインし直す／通信が戻ると、自動で対戦に復帰します（サーバーが現在の問題・得点・解答済みを送り直します）。
- 切断中の人はバナー位置に赤字で「切断」と表示され、未回答扱い。その人以外が全員回答すると次へ進みます。

## セキュリティ設定（Render の環境変数）
- `CLIENT_ORIGIN` に Vercel のURLを必ず設定（未設定だと、どのサイトからでも呼べてしまう）。
- レート制限: 全体 120回/分、ガチャ・ショップ・フレンド・通報・改名は 30回/分（IPごと）。
- helmet でセキュリティヘッダーを付与。API の応答は `no-store`（設定を変えたらすぐ反映）。

## その他
- マスター帯(MR)では連勝ボーナスは付きません。
- bot の解答時間は、同じ帯の平均 ±3 秒以内。平均付近が最も多く、離れるほど少しずつ出にくい（頂点は毎回少しずれる）。

## ガチャの抽選
最初に「レア度ごとの確率」でレア度を決め、そのあと「砂の確率」で砂かアイテムかを決めます。そのレア度のアイテムがガチャに入っていないときは砂になります。

## バナー（台紙）の元画像

## マッチング画面・フレンド申請
- 「対戦相手が見つかりました」の画面は、プロフィールと同じバナー（台紙・アイコン・キャラ・名前・ランク・バッジ）で表示します（対戦中の帯は従来どおり）。
- フレンドコードを入力して「確認」を押すと、相手のバナーが出ます。「この人に申請する」で申請します。確認用の検索は 20回/分まで。

`docs/icon-ring-template.png`（ガイド付き）と `docs/icon-ring-template-guides.png`（ガイドだけ・透過）。1024×1024。標準の位置調整では、アイコンは画像の中央・直径83.3%（853px）に表示されます。

## ピックアップ・排出率・販売の一括切替
- 管理画面 → ガチャ → 各ガチャの編集で「ピックアップ」を選ぶと、そのレア度でアイテムが出たとき、選んだアイテムは2倍出やすくなります。
- ガチャ画面の提供割合には、アイテムごとの排出率(%)が出ます（上ほどレア）。
- 管理画面 → アイテム で、レア度（と種類）を選んで販売／非売を一括で切り替え。名前検索・並び替えもできます。

## ミッション（デイリー／ウィークリー／スペシャル）
- 3種類とも管理者画面の「ミッション」で登録します。デイリーは初回起動時に従来の3つ（ログイン・5マッチ・3勝）が自動登録されます。
- デイリーは毎日0時、ウィークリーは毎週月曜0時（JST）に進捗がリセットされ、日付指定なしでずっと回ります。スペシャルのみ開始・終了日時を指定できます。

## 天井システム
- ガチャごとに専用ゲージ（上限200）。1回引くごとに+1（10連は+10）で、ユーザー文書の `pity` に既存の更新と一緒に保存します（追加の読み書きなし）。
- 200に達すると、そのガチャのレジェンダリー（セット含む）から1つ選んで獲得でき、ゲージは0に戻ります（`POST /api/gacha/pity/claim`）。
- ガチャごとの値なので共有・引き継ぎ不可。期間限定ガチャが終了すると、そのゲージは表示されなくなります。
- ガチャ画面の左下にゲージと「◯/200」を表示。バナー読み込み前は灰色の「Now loading」を表示します。

## キャラ（レジェンダリー）とアイコンの紐づけ
- 管理者画面のアイテム一覧で、キャラに「アイコン」を紐づけられます。そのキャラをガチャ・天井で獲得すると、紐づけたアイコンも自動で付きます。
- 紐づけたアイコンは単体ではガチャから出ません（キャラ経由でのみ入手）。
